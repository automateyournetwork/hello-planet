# Contributing

Start with a small issue or spec explaining the user experience, source data, and acceptance criteria. Fork the repo, keep changes focused, and include the output of `npm run check`, `npm test`, and `npm run build`. For visual changes, include desktop/mobile screenshots and describe keyboard/no-WebGL behavior. Run PHP tests when changing that collector.

Keep demonstration data explicitly labeled. Don't commit real visitor events, keys, MMDBs, or private backups. Preserve third-party notices and document geographic sources. New telemetry needs an explicit data contract and retention plan. Roadmap ideas in README are invitations, not promises.
